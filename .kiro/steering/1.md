# SaveBetter Development Guidelines

## Project Architecture

Monorepo personal finance application with:
- `savebetter-backend`: Node.js/Express API with PostgreSQL
- `savebetter-mobile`: React Native/Expo mobile app  
- `savebetter-desktop`: Electron desktop app
- `savebetter-dark`: Next.js web app
- `shared`: Common TypeScript types and business logic

## Critical Rules for AI Assistant

- **Error-first approach**: Always fix compilation/runtime errors before implementing new features
- **Strict TypeScript**: Use `strict: true`, never use `any` types - prefer proper interfaces
- **Repository pattern mandatory**: All database operations must go through repositories extending `BaseRepository`
- **Shared types hierarchy**: Define core types in `shared/src/types/index.ts`, extend in backend `src/types/index.ts`
- **Test-driven development**: Write tests for new functionality, run existing tests before changes

## Database Layer

- **ORM**: Knex.js for queries, migrations, and seeds
- **Primary keys**: Always use UUIDs, never auto-incrementing integers
- **Base entity**: All entities extend `BaseEntity` with `id`, `createdAt`, `updatedAt`
- **Repository base**: Extend `shared/src/database/repository.ts` for all data access
- **Naming**: Entity interfaces end with `Entity` suffix (e.g., `UserEntity`)
- **Migrations**: Use descriptive names, include rollback logic

## API Design Standards

- **Endpoints**: RESTful `/api/v1/resource` pattern
- **Response format**: Always use `ApiResponse<T>` wrapper
- **Validation**: Joi schemas for all request validation
- **Status codes**: Use appropriate HTTP status codes (200, 201, 400, 401, 404, 500)
- **Authentication**: JWT tokens with bcrypt password hashing
- **Error handling**: Consistent error response format

## TypeScript Configuration

- **Path mapping**: Use `@/*` aliases for src root across all projects
- **Targets**: ES2020 for backend, platform-specific for frontends
- **Strict mode**: Enable all strict TypeScript checks
- **Type safety**: Prefer interfaces over types, use generics appropriately

## Testing Strategy

- **Framework**: Jest for all projects
- **File naming**: `.test.ts` for unit tests, `.test.tsx` for component tests
- **Organization**: Tests in `__tests__` directories alongside source
- **Coverage**: Write descriptive test names, include setup/teardown
- **Integration**: Separate unit and integration test files

## State Management (Redux Toolkit)

- **Slice organization**: Domain-based slices (user, goals, transactions, banking, assessment)
- **State structure**: Normalized state with proper TypeScript typing
- **Actions**: Use createAsyncThunk for API calls
- **Selectors**: Create reusable selectors for complex state access

## Component Architecture

- **Component types**: Functional components with hooks only
- **UI components**: Reusable components in `components/ui/`
- **Screen components**: Page-level components in `screens/`
- **Custom hooks**: Business logic hooks in `hooks/`
- **Naming**: PascalCase for components, camelCase for utilities and hooks

## File Organization Patterns

- **Feature grouping**: Group by domain/feature, not file type
- **Index exports**: Use index files for clean imports
- **Co-location**: Keep related files together (component + styles + tests)
- **Barrel exports**: Export from index files to simplify imports

## Security Requirements

- **Environment variables**: All sensitive config in .env files
- **Input validation**: Server-side validation for all inputs
- **Middleware**: Use CORS, helmet, and rate limiting
- **Authentication**: Secure JWT implementation with proper expiration

## Development Workflow

- **Setup**: `npm run install:all` for initial setup
- **Development**: `npm run dev` starts backend and mobile concurrently
- **Testing**: `npm run test` runs all workspace tests
- **Type checking**: `npm run typecheck` verifies TypeScript across projects
- **Code quality**: Fix TypeScript errors before proceeding with implementation
